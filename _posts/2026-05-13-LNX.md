User의 Home directory는 보통 ~ 로 표시가 됨, 그렇기에 지금 ls -l로 보이는 -의 파일이 read가 가능한 파일인것을 알 수 있다. <br>
`cat ./-` `cat -`대신 `./-`를 명령어에 써서, 상대경로로 전달한다. 상대 경로로 -를 읽기 때문에 옵션이 아닌 현재 디렉토리 내의 파일을 확인하게 되며 password를 확인할 수 있다.<br>

#### Memo
`cat -`가 안되는 이유? cat에서 `-`를 사용한다면 stdin(표준입력)으로 인식한다. 또한 리눅스 내에서 -는 특수기호로 다양한 역할을 가지고 있다. <br>
`-rw-r-----`로 보이는 것은 권한에 대한 부분과 파일 종류를 나타낸다. <br>
- 맨 앞에 무엇이 오는가에 따라 해석
    - `-`: 일반 파일
    - `d`: 디렉터리
    - `l`: 링크 파일
- `rw-` / `r--` / `r--` 순서대로 `소유자(owner)`, `그룹(group)`, `다른사용자(other)`로 권한 여부가 설정됨을 볼 수 있다. <br>

#### Memo

리눅스 find 명령어 사용법: `find [옵션] [경로] [표현식]` <br>

Example) 현재 위치에서 log가 들어가는 파일 모두 찾기 : `find . -name "\*log\*" <br>

- find [옵션] [경로] [표현식]
- find의 인자값으로는 경로를 받는다. 상대 경로, 절대 경로 모두 가능하며 대부분의 리눅스의 경우 경로 인자 값을 생략한다면 현재 위치(.)를 입력받은 것으로 간주하지만 유닉스의 경우 이 경로를 입력받지 않으면 명령어 실행이 안된다.
- 옵션:
    - P: 심볼릭 링크를 따라가지 않고 심볼릭 링크 자체 정보 사용
    - L: 심볼릭 링크에 연결된 파일 정보 사용
    - H: 심볼릭 링크를 따라가지 않으나, Command Line Argument를 처리할 땐 예외
    - D: 디버그 메세지 출력
<br>
- 표현식:
    - name: 해당 이름의 파일을 찾음, 해당 이름에는 정규 표현식을 활용할 수 있음
    - type: 지정된 파일 타입에 해당하는 파일 검색
    - user: 해당 유저에게 속한 파일 검색
    - empty: 빈 디렉토리 혹은 크기가 0인 파일 검색
    - delete: 검색된 파일 혹은 디렉토리 삭제
    - exec: 검색된 파일에 대해 지정된 명령 실행
    - path: 지정된 문자열 패턴에 해당하는 경로에서 검색
    - print: 검색 결과를 출력, 검색 항목은 newline으로 구분
    - print(): 검색 결과를 출력, 검색 항목은 null 로 구분
    - size: 파일 크기를 사용하여 파일 검색
    - mindepth: 검색을 시작할 하위 디렉토리 최소 깊이 지정
    - maxdepth: 검색할 하위 디렉토리의 최대 깊이 지정
    - atime: n일 이내에 액세스 된 파일을 찾음
    - ctime: n일 이내에 만들어진 파일을 찾음
    - mtime: n일 이내에 수정된 파일을 찾음
    - cnewer file: 해당 파일보다 최근에 수정된 파일을 찾음

<br>
find 명령어는 다른 명령어와 달리 옵션은 거의 사용되지 않고 표현식을 통해 찾을 타깃을 정한다. 표현식은 중첩이 가능하며 범위를 더 줄일 수 있다. <br>

* 파일 크기로 찾기 (-empty, -size)

- 현재 디렉토리에서 빈 디렉토리이거나 크기가 0인 파일 검색
    - find . -empty
- 현재 디렉토리에서 test가 들어가는 빈 디렉토리이거나 크기가 0인 파일 검색하여 삭제
    - find . -name "\*test\*" -empty -delete
- 현재 디렉토리에서 1024byte인 파일 검색
    - find . -size 1024c
- 현재 디렉토리에서 1024byte보다 큰 파일 검색
    - find . -size +1024c
- 현재 디렉토리에서 1024byte보다 작은 파일 검색
    - find . -size -1024c
- 현재 디렉토리에서 1kb보다 크고 10kb보다 작은 파일 검색
    - find . -size +1k -size -10k

* 단위: b(블록단위), c(byte), k(kbyte), w(2byte 워드)

#### Memo
##### sort
- 파일 내용을 줄 단위로 정렬하는 명령어이다.
- 사용법: `sort [OPTION].... [FILE]...`
    - -n: 숫자를 기준으로 (numeric sort)
    - -r: 역순으로 정렬 (reverse)

- 연속으로 중복된 줄을 제거하거나 확인하는 명령엉이다.
- 사용법: `uniq [OPTION]... [INPUT [OUTPUT]]`
    - -c: 중복된 줄 개수 출력 (number of occurrences)
    - -d: 중복된 줄만 출력 (only print duplicate lines)

<p>To gain access to the next level, you should use the setuid binary in the homedirectory. Execute it without arguments to find out how to use it. The password for this level can be found in the usual place (/etc/bandit_pass), after you have used the setuid binary.</p> <br>
<p>홈 디렉터리에 있는 setuid 바이너리를 사용해서 평소처럼 /etc/bandit_pass에서 비밀번호를 찾으라는 것 같다. </p>

### Approach
![bandit19 solve](/assets/img/posts/LNX/bandit19-solve.png)

`setuid`는 set user id의 약자로 한 파일이나 디렉토리를 사용할 때 그 파일의 소유자 권한으로 실행이 되는 것을 말한다. <br>
`ls -l`를 사용했을때 사진에 보면 `<owner>` 부분에서 `rws`로 적혀있는데, s가 있는 부분을 setuid가 설정된 파일임을 의미한다. <br>
`bandit20-do`는 현재 bandit20이 소유주로 되어있다. 즉, bandit20-do 를 사용한다면 bandit20이 실행하는것으로 간주하는 것이다. <br>
<br>
두번째에서는 `./bandit20-do`로 직접 실행을 해보는데, `Example ./bandit20-do whoami`하라며, 실제 실행해보면 whoami의 결과가 bandit20으로 되는것을 볼 수 있다. <br>
따라서 `./bandit20-do cat /etc/bandit_pass/bandit20`으로, 비밀번호가 있는 파일인 /etc/bandit_pass/bandit20을 bandit20의 권한으로 실행시킨다. <br>

Job Control은 쉘(Shell)에서 여러 프로세스를 관리하는 기능이다. 실행중인 프로세스를 foreground/background로 전환하거나, 일시중지, 재개 종료 하는것들을 말한다.

<br>
- Foreground: 터미널을 점유하고 실행중인 프로세스, 입력을 받음
- Background: 터미널 뒤에서 돌아가는 프로세스, 터미널은 계속 사용 가능

| 명령어 / 단축키 | 동작 |
|:------:|:------:|

| bg | background로 재개 |
| fg | foreground로 복귀 |
| 명령어 & | 처음부터 background 실행 |
| jobs | job 목록 확인 |
| fg %1 | 특정 job을 fg로 |
| kill %1 | 특정 job을 종료 |
